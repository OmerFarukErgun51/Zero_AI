# ZeRo v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build ZeRo — an offline, JARVIS-flavoured Windows desktop assistant that chats, reads Outlook mail/calendar (read-only), plans the day with reminders, nudges breaks, generates Office documents, and remembers the user across sessions.

**Architecture:** A long-running background Python app (system-tray + HUD chat window) orchestrates focused modules. A local LLM runs via Ollama, loaded on demand (not resident). All personal data lives in a local SQLite store (optionally under OneDrive for cross-machine sync). Every subsystem degrades gracefully when its dependency (Outlook COM, Ollama) is unavailable.

**Tech Stack:** Python 3.11+, Ollama (`ollama` python lib) with a ~4B Q4 model + `nomic-embed-text` for embeddings, `pywin32` (Outlook COM + activity/idle), `PySide6` (tray + HUD chat UI), `windows-toasts` (notifications), `APScheduler` (scheduling), stdlib `sqlite3` (memory), `openpyxl` / `python-pptx` / `python-docx` (documents).

**Spec:** `docs/2026-10-26-zero-masaustu-asistani-tasarim.md`

## Global Constraints

- Language: Python 3.11+. All code and user-facing strings in Turkish (persona + UI).
- **Offline at runtime:** no core feature may require internet. Only first-time setup (Ollama install, `ollama pull`) uses the network.
- **Model lifecycle:** model is NOT kept resident; loaded on demand with a short keep-alive (default `keep_alive="5m"` on Ollama calls), then released.
- **Outlook:** classic Outlook COM only (`win32com.client`, `Outlook.Application`). READ-ONLY plus reply *drafts*. ZeRo must never send mail and never write to the calendar.
- **Privacy:** all personal/mail/conversation data stays on the local machine. Memory root defaults to a local path and may be pointed at a OneDrive folder; nothing is uploaded by ZeRo itself.
- **Graceful degradation:** if Outlook COM or Ollama is unavailable, ZeRo stays running, tells the user plainly in Turkish, and keeps every unaffected feature working.
- **Resource budget:** idle footprint (excluding the model) must stay light; no busy-wait loops — use scheduled/event callbacks.
- Hardware target: CPU-only inference, ~4B Q4 model, 16 GB RAM.

## Review Focus

1. **Outlook COM blocked/absent** (corporate policy, "New Outlook" only, or Outlook not running): mail/calendar features must disable themselves with a clear Turkish message; chat/plan/health/documents keep working. — covered in Task 7.
2. **Ollama not running or model not pulled:** ZeRo detects it, shows a plain fix message, never crashes; non-brain features stay usable. — covered in Task 3.
3. **Context overflow from long history:** retrieval must bound what it sends (profile summary + top-k snippets) so the model's context window is never exceeded. — covered in Task 4.
4. **First run / empty memory:** no profile yet — ZeRo must work without crashing and start building the profile over time. — covered in Tasks 4 & 5.
5. **Malformed free-text plan** ("bugün bi şeyler yapıcam", no times): the parser returns a sensible result or asks to clarify rather than crashing or inventing times. — covered in Task 10.
